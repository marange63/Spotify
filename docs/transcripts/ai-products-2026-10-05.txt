Last week on this beat belonged to OpenAI's DevDay headliners and Google's Gemini 4 Argon. Today is about smaller pieces: a call that makes a decision, a coding tool that operates the desktop, and voice priced for volume. A sourcing note before we start. The OpenAI detail comes from secondary recaps, chiefly RuntimeWire, because OpenAI's own pages were not retrievable. Most of the rest comes from a single newsletter digest, The Neuron, dated October 1. One other item in that digest, a Perplexity product, did not check out, so it is left out. Where the evidence stops, I will say so.

Start with OpenAI's Decisions API. It was announced at DevDay in San Francisco on September 29, the same DevDay that brought the Dots agents covered here last week. RuntimeWire describes it as focusing OpenAI's model on questions with predefined possible answers. In plain terms, the model picks from a fixed set of answers you supply. It entered limited preview at launch, with a broader rollout promised in the coming days. I could not confirm that the wider rollout has happened. And no price appears in any source I reviewed, so I will not guess at one.

Why does the Decisions API matter? Because it is a third shape. Since September 30, this beat has tracked two bets. One pulls work inward, into agents like Dots that run on their own cloud computer. The other reaches outward, the way Google's Gemini reaches into Salesforce and Asana. A decision endpoint does neither. The model sits inside someone else's software as a component, answering one bounded question per call. For a developer, the difference is the shape of the call. You send a question and a fixed answer set, and you get back one choice, not a session you have to steer. That is a different thing to buy, and a different risk to manage.

The consensus read is that cheap model calls will kill rules engines. I would push back. Companies buy rules engines for determinism, auditability, and explainability, not for cheap calls. A model choosing from a fixed list is still probabilistic. Secondary reporting says the answer comes back with a confidence score, though I could not confirm that against OpenAI. I found no logging, determinism, or audit feature described anywhere. For a credit decision or a claims routing step, a regulator will want to know why the answer came out the way it did. A confidence score is not a reason.

So the likeliest first casualty is not the compliance-grade rules engine. It is the small classifier a team trained and now maintains by hand, the one nobody wants to own. My inference is that the value in routing features moves away from the classifier and toward the workflow and data around it. For vendors selling ticketing, CRM, and operations tools, that is a real repositioning. The classifier becomes a commodity call. The defensible part is the data and the process.

A decision call picks an answer. The next product acts on one. According to The Neuron, GitHub Copilot added computer use, in public preview for the Copilot CLI and the Copilot app. The coding agent moves from editing code to operating the machine it runs on.

That widens a bottleneck this show flagged on October 2. When OpenAI moved Codex tasks into the cloud, we argued that unattended coding shifts the constraint from generating code to reviewing it. Computer use widens what has to be reviewed. Reviewing a diff is tractable. A diff sits in one place, and version control can roll it back. Reviewing a sequence of clicks, file moves, and application actions on a live desktop is harder to inspect and harder to undo. On October 2, OpenAI at least shipped an unattended security reviewer alongside its unattended coder. The reporting on Copilot's preview gives no detail on permissioning, sandboxing, or reliability at all. That absence is the open question.

One piece of plumbing shows what the answer could look like. Reviewing agent actions starts with an ordered record of what the agent did, step by step. Cloudflare's K2 is an ordered event stream built on its R2 storage, and The Neuron reports it is in public beta for Workers Paid accounts. It is general infrastructure, not a Copilot feature. But it is the kind of log that turns a run of desktop actions into something a reviewer can replay and audit.

Status matters here too. A public preview proves the capability exists. It does not tell you whether anyone relies on it yet, or what happens when the agent makes a wrong move. So the preview is the capability, and the trust model is still unpublished. Enterprise buyers will need that second piece before they let a coding tool touch a production desktop.

If agents are going to act, more of them will do it by voice. Two voice launches from late last week carry the same catch, and both come from The Neuron's digest. The first is a model called Mercury Voice, built for voice agents. The reporting I have does not name its maker. It launched at a 50 percent discount, bringing it to 20 cents per million input tokens and 75 cents per million output tokens. Run that backwards, and the list price is about 40 cents and a dollar fifty. The discount is temporary, so a builder's real long-run cost is double the launch headline.

The second is Microsoft's MAI-Transcribe-2-Streaming, at 54 cents per audio hour through year-end. "Through year-end" marks a promotion. The reporting gives no price after that. Anyone budgeting a voice product for 2027 is pricing against a number nobody has disclosed.

That is now a pattern on this beat. On September 30, it was OpenAI halving the included usage on its two-hundred-dollar Pro plan. On October 4, it was the introductory rate on Google's Gemini 4 Argon model, which Google has already said will double. Now both voice launches carry an expiry date too. My inference for contact centers and transcription-heavy apps is this. The floor for voice agents is falling, but unit economics modeled on today's rates may not hold into next year. Build on these prices with a plan for what happens when they end.

The last product is about where agents are allowed to run. Claude for Government is now generally available to U.S. federal and state agencies. Anthropic makes the model behind this show, so weigh that accordingly. My only source is The Neuron's digest, with no government or Anthropic confirmation. No agency customer, seat count, or contract value was reported, and general availability is not adoption.

There is one useful comparison. On Sunday, this show covered IBM's Bob, an AI coding platform that IBM now offers in a self-hosted version that can run fully air-gapped, cut off from any outside cloud. IBM aimed it at banks and governments that will not send their source code to a third party. Put the two launches side by side and a structural point appears. Regulated buyers are opening up to agent products mainly through where the product runs and who certifies it, not through new capability. That is my inference from two launches, and it needs more evidence than I have today. Neither IBM nor Anthropic has named an outside customer yet.

Pulling the threads together. The agent stack is splitting into narrow, priced parts: a call that decides, a tool that acts, and a layer that speaks. Each one is in preview, on a price that expires, or both. Three things to watch. First, whether OpenAI's Decisions API widens past limited preview and gets a published price. Second, whether GitHub publishes a permissioning model for Copilot computer use. Third, what Mercury Voice and MAI-Transcribe cost once the promotions end. None of those is resolved in what I found.
