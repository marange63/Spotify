Good morning. It's Wednesday, August 19th, and this is your AI products briefing.

The theme running through the last several days of this show has been value migrating below the model — into routing and billing, into the browser as a work surface, into enterprise governance. Today it moves one layer deeper still: into the plumbing that connects agents to tools in the first place.

Let's start there. On July 28th, Anthropic and the Model Context Protocol steering group shipped the largest revision to MCP since the protocol launched. The core change is this: MCP drops its old bidirectional, session-based handshake — the persistent connection a server had to keep open — in favor of a stateless request-response model, where every call describes itself. Anthropic put it plainly: MCP moves from a bidirectional stateful protocol to a request-response model, and servers can now deploy on serverless and edge infrastructure. That's not a small technical footnote. It means a small team can now ship an enterprise-grade agent connector without running an always-on process to keep it alive, which directly lowers the cost of building the tool layer that every enterprise copilot depends on.

This isn't just Anthropic's own telling. Cloudflare shipped support for the new spec the same day it was published, across its Agents SDK and its own product-specific MCP servers, and described exactly the mechanic at work: each request now runs on a fresh, stateless server with no session object required. Cloudflare's own Code Mode MCP server, live since February, has scaled to thousands of requests per second and served billions of tool calls — real production load, not a demo, and independent confirmation that the serverless model holds up under weight, even if Cloudflare doesn't explicitly say that specific server was blocked from running this way before.

The spec also standardizes a few other things worth knowing: server-rendered interfaces inside a chat window, a formal path for long-running asynchronous tasks, and — this is the quieter but arguably more consequential piece — authorization that aligns with production OAuth 2.0 and OIDC deployments, so MCP servers plug into enterprise identity systems like Entra or Okta without workarounds. That matters because auth, not model quality, is often the actual gate that keeps security teams from approving agent connectors in the first place. Fix that gate and you open the door for a much longer tail of vertical integrations beyond today's handful of big-name connectors. The upgrade isn't free, though. The same spec deprecates the older transports on a twelve-month clock — including the HTTP-plus-SSE transport that a lot of existing servers were built on — so every team already running an MCP server has migration work coming, a near-term tax on the very ecosystem these numbers describe.

Now, on scale: Anthropic says its connectors directory lists over 950 MCP servers, used by millions of people daily, and that MCP SDK downloads have quadrupled this year to more than 400 million a month. Treat those specific numbers as self-reported — nobody outside Anthropic has verified them. What independent evidence does exist points the same general direction without confirming the exact figures: the public MCP Registry counted roughly 9,652 servers as of this past May, a different and broader scope than Anthropic's curated directory, and a vendor survey from Stacklok found 41 percent of the software organizations it surveyed already running MCP servers in limited or broad production. So the underlying trend — real, growing production adoption — looks solid. The precise headline numbers do not have a paper trail. And to be clear about freshness: the spec itself is three weeks old; what's new this week is evidence the serverless benefit is actually showing up in shipped infrastructure, not that Anthropic just launched something. So what this adds up to: the tool layer every AI product depends on just got structurally cheaper and easier to build, and the auth fix may do more for enterprise adoption than any model upgrade this month.

That plumbing only pays off, though, if the assistant sitting on top of it can actually reach the documents and context you already work in. That's where ChatGPT's latest update fits. OpenAI has started rolling Google Drive directly into ChatGPT's Library: you can now browse Drive files and folders — including ones shared with you — right inside ChatGPT, pull a document into a chat with an @-mention with no re-upload required, and keep a Doc, Sheet, or Slide open alongside the conversation for summarizing or comparison. It's rolling out first to Plus, Pro, Enterprise, Edu, Healthcare, and Business users on the web, with mobile to follow. The point of this feature isn't novelty, it's friction removal: ChatGPT stops being a separate silo you copy-paste into and starts being a working surface sitting on top of Workspace documents you already have. That's a direct competitive wedge into Google's own customer base, at the exact moment Google is pushing Gemini as the native Workspace copilot.

Alongside that, the Mac app added an opt-in feature called Computer History, replacing an earlier feature named Chronicle. When turned on, it lets ChatGPT and Codex reference selected activity from other apps and websites you've used, so you don't have to re-explain context every session. Worth being precise about what it is and isn't: it records interaction events only — not screenshots, not screen recordings, not microphone or system audio — private browsing is excluded, it's off by default, and it's limited to Pro, Business, and Enterprise users. One outlet has separately reported that Computer History's log files may be stored unencrypted on the device; that claim comes from a single secondary source, is not corroborated, and should be treated as unverified rather than fact. The broader pattern here is the same one showing up in MCP: whichever assistant manages to own your existing context — your files, your recent activity, your connectors — becomes the one that's hardest to switch away from, because switching means re-explaining everything from scratch.

Let's close with a brief reality check on whether any of this build-out is actually converting into revenue. Bloomberg, citing investors and unnamed sources, reports Anthropic's annualized revenue run rate surpassed 65 billion dollars at the end of July, up from 47 billion in May and just 9 billion at the end of last year — investors reportedly expect the full year to land between 100 and 120 billion. Treat that as unaudited, secondhand reporting on a private company, not a filed disclosure, and note the source doesn't break out how much is Claude Code, API usage, or enterprise seats — there's no product-level attribution here, just a topline trend. It's the best available proxy that Claude Code and enterprise Claude deployments are producing real usage rather than demos, but it's worth noticing, as a pattern across today's whole briefing, that nearly every load-bearing number we've cited — MCP's server count, its download figure, Anthropic's revenue run rate — comes from the vendor itself or from unnamed sources, with no independent audit trail. That's not a reason to dismiss any of it. It's a reason to hold the scale claims a little more loosely than the mechanics claims, which today's Cloudflare evidence actually did verify.
