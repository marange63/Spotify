More caveats belong here. These cost figures come from a secondary summary of LiveBench's leaderboard, not the live page. Cost per successful task also depends on the test harness. First, buyers who procure on cost per task will route work model by model. That lowers switching costs and pushes the coding layer toward commoditized infrastructure, not a winner-take-most market. Second, Anthropic's premium now has to be earned on something LiveBench doesn't measure, like long-horizon reliability or data trust. Absent that, a fivefold cost gap is a share-loss risk.

Google's cost edge ultimately rests on its own chips, and that roadmap reportedly just hit a snag. Supply-chain reporting puts packaging yields on Google's next-generation TPU, the v9, at around forty-five to fifty percent. Front-end fabrication stays at TSMC throughout, so the problem is packaging, not the chip itself. None of this is confirmed by Google. And a 2028 shipment date changes nothing about Gemini's serving costs today. If the slip is real, Google leans on Nvidia and its current TPUs for longer than the custom-silicon story implied. That would support Nvidia demand, and cost Intel a showcase packaging customer. The takeaway: a lead on score is not a lead on future unit cost.

Now to Anthropic's weak flank, which is cost. This week Anthropic published an engineering post that is explicitly about cost. It rewrote its Messages API from Python to Rust, largely using its own Claude agents. Anthropic reports the rewrite cut CPU use per request by about seventy percent, and memory by more than eighty percent. Median time to first token fell about twenty percent.

The agentic-coding details are the striking part. Claude agents wrote more than eighty percent of the merged code. The team had no prior Rust developers. And a first working version of the core request path came together in about a week. Human engineers did the verification, though, so merged-code share isn't the same as share of engineering effort.

The contrast that matters is an earlier attempt. In March, a narrower port moved only response parsing to Rust, and it saved just eight to ten percent of CPU. Each reply still crossed the Python-Rust boundary three times. The full rewrite skipped that overhead entirely. That's the real signal: agents can make whole-system rewrites economical where boundary patches fell short. If that generalizes, it threatens legacy-migration consulting revenue and hands Anthropic a sales pitch for its coding products. That part is our inference.

It also cuts against an anecdote we relayed on November 23rd. Developer Theo Browne spent seven days on a Rust compiler rewrite using GPT-6.2 Astra, without landing a speed improvement. Both are anecdotes, not base rates.

Here's the necessary caveat on the Rust rewrite. It's self-reported by Anthropic about its own infrastructure, with no outside verification. Critically, it measures CPU on the API serving layer, not the accelerator time that drives model inference. So it doesn't obviously close the nine-eighty-five versus one-ninety-four gap from the lead. It's real overhead savings and a strong agentic-coding proof point. It isn't yet a fix for the per-task cost problem.

One more axis that isn't about capability at all: enterprise trust. We noted yesterday that OpenAI is alpha-testing Private Inference. It runs enterprise workloads inside hardware-isolated enclaves, so prompts stay hidden even during processing. It's a small customer group, with no general-availability date or pricing. The new piece today is the competitive map. Apple, Cohere, Microsoft, and Google already offer confidential-computing inference. Whether regulated buyers will insist on one isn't yet shown. Treat it as a differentiation risk, not a lost deal.
