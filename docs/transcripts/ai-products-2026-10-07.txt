Before we start, a disclosure. Anthropic makes the model behind this show, and today's lead story is an Anthropic product. Weigh what follows with that in mind.

Over the last few days, this beat has been about where AI agents run and who pays for them. Today is about a different question: who gets the controls.

Our lead is Claude Code Mods. Anthropic shipped Mods for its coding agent on October 1. The Claude Code changelog ties them to version 2.1.287, and Anthropic's admin documentation says mods are on by default.

A mod is a small TypeScript function that changes how Claude Code works. In Anthropic's own words, a mod can rewrite a prompt, add new UI, replace a built-in feature, or add entirely new functionality. Mods ship inside plugins. Users install them with the plugin command or download them from the Claude directory.

So what can a mod actually do? It can rewrite a prompt before the model sees it. It can block, rewrite, or retry a tool call. It can approve a tool call that would otherwise prompt the user, or deny one outright. That is the difference between a product and a runtime. A team can now change how the agent behaves without forking the tool.

The clearest signal is what Anthropic did with its own features. The built-in diff feature is now a mod. Users can turn it off in the plugin menu, or replace it with their own version. A vendor's default behavior has become a replaceable default.

There is a limit to that, and it matters. Anthropic's admin docs say a user's mod cannot change the system prompt, managed hooks, or an organization's managed instructions. So the user-facing features are replaceable. The managed security core is not.

Here is why Mods matter beyond coding. Yesterday's point was that vendors are selling agents that act on their own faster than they are publishing rules for what those agents may do. Mods are the first shipped answer to that gap. The answer is that the buyer writes the control. But Anthropic's own documentation supplies the catch. A mod runs with the same access to your machine as Claude Code itself. It is not sandboxed. The admin documentation says it again. A user's mod can still read and write files, start processes, and make network requests, all with that user's permissions.

The fair correction is that Anthropic does ship an admin layer. On Team and Enterprise plans, an owner can allow or block plugin marketplaces in the admin console. A built-in security guard loads first on those plans. It stops user-installed mods from overriding permission deny rules. And a single admin switch allows only company-approved mods, so no user-installed mod loads at all. Anthropic says the guard reads its options from managed settings only, so a user's own settings file cannot undo that.

One caveat on the security guard itself. Its deny-rule protection can be disabled. With that protection disabled, a user's mod that approves tool calls can approve a call a deny rule refuses.

So the controls are partial, not absent. An admin decides which mods run. Beyond the guard's short list of protections, nothing in the product limits how far a running mod can reach. There is no sandbox, and no per-mod review. So the practical question for enterprises is no longer whether a control exists. It is whether the default is right. Because mods are on by default, admins have to act to turn them off. My inference is that the simplest lockdown, that single admin switch, will often win over vetting each mod one at a time.

Now the second-order effects. First, a plugin directory becomes a distribution layer for agent behavior, not just for tools. Last week, on September 29, this beat flagged Anthropic's reviewed plugin directory, which has no disclosed take rate and no disclosed rejection criteria. Mods ship through that same channel. Whoever curates the directory sets the terms for what runs inside the agent.

Second, switching costs cut both ways. Replaceable built-ins lower the cost of bending Claude Code to a team's workflow. But every mod a team writes is code that only runs in Claude Code. My inference is that heavy customization makes the harness stickier, not more portable.

Third, for security teams, this is a new supply-chain surface. An extension mechanism inside a coding agent, running with full local privileges, needs the same review as any locally installed program. That is a new job, and it lands on people who did not ask for it.

Now the caveat that matters most for the investment read. There is no adoption data. I found no primary-sourced install counts, no directory size, and no named launch mods from third parties. This is a launch capability, not a track record. Do not read enterprise uptake into it.

So Claude Code Mods make the coding agent extensible. They do not yet make it governable without trust in the people who write the mods.

On the consumer side, the user is also getting a new control: an effort dial. And with it comes the bill.

On October 3, 9to5Google reported changes to the Gemini app's model tiers. I could not locate Google's own announcement, so treat this as one secondary source. Starting October 9, Gemini app users without a Google AI subscription will be limited to the Flash-Lite model. They lose access to Flash and Pro. AI Plus, the paid tier below the $19.99 AI Pro plan, keeps Flash-Lite and Flash but loses Pro. That change has not taken effect yet. It is Google's announced plan, as reported.

The upsell goes the other way. AI Pro itself gains Deep Think, which the report describes as an option for maximum parallel reasoning.

And in October, the app is due to add low, medium, and high effort levels for each available model. That is the dial. As the report summarizes it, higher effort buys more thorough answers at the cost of more of the user's usage limit. That is a stated plan, not a shipped feature, so do not treat it as live yet.

There are two readings of the tier changes, and Google has not stated its reasoning in anything I could verify, so both are inference. The first is cost rationing. Heavy free usage is expensive, so free inference gets cut. The second is upsell design. Moving Deep Think down to the $19.99 tier makes that tier the obvious choice, and the free downgrade pushes users toward it. Both can be true at once. And there is no user-count or conversion data, so how free users respond is unknown.

The effort dial is the more interesting product choice. It turns inference budget into a setting the user can see and adjust. My inference is that other assistants will copy the pattern. So the consumer version of the same story is this: model quality is becoming a metered entitlement, not a default.

That extends a pattern this beat has tracked. On September 30, OpenAI halved the included usage on its existing Pro plan. Launch terms keep moving after launch. Now the movement has reached the free tier of a mass-market assistant.

Last, a brief item from the same Gemini app. Android Headlines reports that Google is replacing Gems with Skills. Skills are reusable instruction modules. A user can invoke one by slash command, let the system select it automatically, or combine several. My read is that Skills play a similar role to Mods, letting users package reusable behavior, but as instructions, not code.

The phase-out schedule is the useful detail. Personal accounts start losing Gems in November 2026. Enterprise and nonprofit Workspace customers transition in March 2027. Education accounts follow in June 2027. Consumers go first, and business and schools trail by months. For Workspace administrators who built on Gems, that is a migration window to plan for.

Two caveats. Skills may be largely a rebrand of Gems with composition added, so do not treat this as a new software category. And the reporting does not say whether existing Gems migrate automatically. That is the question an admin needs answered before March.

Here is the through-line. In both the developer tool and the consumer assistant, control is being handed to the user. The risk and the bill are going with it.

Three things would change this read. First, whether Claude Code Mods get sandboxing or per-mod review, beyond the single admin switch. Second, whether Gemini's effort levels actually ship in October, and how free users respond after October 9. Third, how Workspace administrators handle the move from Gems to Skills before the March 2027 deadline.
