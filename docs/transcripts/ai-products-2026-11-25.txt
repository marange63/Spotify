Good morning. It's Wednesday, November 25th, and this is your AI products briefing.

One disclosure up front. Anthropic makes the model behind this show, and both of today's items are Anthropic's own products. Keep that in mind, because we're going to be extra skeptical of both.

Here's the thesis. Since November 14th, this show has tracked a running pattern: the agent launches we covered kept a human in the approval seat. That pattern just broke, and the replacement is a policy file. Governance is moving from something a person does to something a team writes and checks into a repository.

Start with the lead. On Monday, November 23rd, Anthropic launched Claude Ship, a set of three agents that work on GitHub pull requests. Code Review is already generally available. The other two, PR Steward and Claude Approvals, are new and in beta. PR Steward fixes failing checks, merge conflicts, and review feedback. After every push, it comments with what it changed and how to undo it. Claude Approvals is the one that matters most. It approves pull requests according to a policy file on the repository's default branch. Developers can try Claude Ship on their own pull requests with a new slash-ship command in Claude Code.

Now the broken pattern. On November 14th, this show noted that every agent launch that week shipped with a mandatory human checkpoint. On November 20th, we covered Google's computer-use agent for Gemini on the Mac, which still lets you approve key actions before they happen. The next day, we covered Replit Missions, which added an AI judge but still listed the actions that need your sign-off. Claude Approvals doesn't have to keep a human at all. And that isn't our guess. Anthropic's own documentation says it plainly. With Approvals on, a pull request can merge with no person but its author looking at it, or with no person at all if a bot wrote it.

There's a boundary built into the design, though, and it's worth being precise about it. Approvals doesn't merge anything itself. Per Anthropic's docs, its check reports who has to approve a pull request, following the policy. That check blocks a merge only if you've made it a required check in GitHub. Your branch rules still decide what merges. What Claude's approving review can do is satisfy a GitHub rule that requires one approval. So the branch-protection machinery survives. What's gone is the guarantee that the approval behind it came from a person.

The policy file is where the real choices live. Claude can post an approving review only if every rule that applies agrees and every changed file is covered. That default leans cautious. If no rule covers a changed file, Claude simply doesn't approve the pull request. But Anthropic's reference docs add a sharper line. Where a rule reads no classifier, Claude can approve a change that no review has read. So whether a person, or even a model review, ever touches the code depends on how the policy author writes the rules. The feature's existence doesn't settle it.

One practical risk follows, and it's our inference. Plenty of teams require exactly one approval before code merges. Turn on Approvals, and Claude's review can fill that one slot. Unless the policy also asks for a person, nobody may notice that no human looked at the diff.

The design does draw one hard line. Per Anthropic's announcement, PR Steward is designed not to approve or merge pull requests. Fixing and approving sit with separate agents on purpose. That separation of duties is the safety argument. One question the docs leave open is whether Approvals can approve a pull request that PR Steward just modified. Adjacent documentation suggests it's treated like any other bot-authored change, but nothing says so directly.

So is this a real trust shift, or just a faster rubber stamp on low-risk changes? The mechanism permits both. With no adoption data, we can't yet tell which use will dominate.

Now the terms, and the skepticism. Claude Ship runs on GitHub repositories, on Team and Enterprise plans only. It's explicitly unavailable to organizations with Zero Data Retention, the HIPAA configuration, or customer-managed encryption keys. That's the sharpest problem with the pitch. The regulated customers who'd most want codified, auditable approval policy are the ones locked out for now.

There's no published list price either. Instead, eligible Enterprise organizations can claim at least ten thousand dollars in Claude Ship credits, to be used within thirty days. The claim deadline is January 15th, 2027. Beyond that grant, usage is billed on tokens, and admins can set spend limits for Code Review and PR Steward. Our reading is that Anthropic is buying usage data before it commits to a durable price. That echoes Replit Missions, which we described on Saturday as priced one enterprise conversation at a time. There are no adoption figures yet. And one more gap. The policy and GitHub-rules documentation we reviewed doesn't describe an audit log. Beyond the GitHub review itself, there's no stated record of each approval decision.

So what does this mean? The scarce human role shifts from reviewing every line to authoring the policy file. Whoever owns that file holds the real control. That makes it a versioned governance artifact, one that compliance and security teams will want to claim. On Sunday, this show argued that the admin was becoming the real gatekeeper of what an AI tool does. Claude Approvals pushes that gate into the repository itself. All of that is our inference, not Anthropic's claim.

There's a competitive angle too, and it's also our inference. Standalone code-review tools, and GitHub's own Copilot review features, now face a model vendor bundling review, repair, and approval into one workflow. The contest shifts from who writes the best review comment to who owns the merge decision. GitHub still keeps the venue, though, because Claude Ship runs on GitHub.

Not every vendor is removing the human gate. Yesterday, our Enterprise Technology desk covered Databricks' Genie ZeroOps agent, which is in public beta. It proposes data-pipeline fixes only as pull requests. Databricks says it never changes code or data without direct approval. So two vendors, within about a week, gave opposite answers. One keeps the human gate as a safeguard. The other treats it as a bottleneck worth automating. Nobody has proven which bet is right yet.

If a policy file decides what an agent may approve, the next question is what an agent is able to do in the first place. That's being packaged too.

On Tuesday, November 24th, Anthropic moved Skills over MCP into public beta for Claude and Claude Code. It lets Claude load reusable skill packages from MCP servers. It's on by default for Pro, Max, and Ultra, and Claude Code needs version 2.1.331 or later. Two existing protocol extensions, Tasks and Elicitation, reached general availability on those same tiers. The shift is that the Model Context Protocol stops being just a connection layer. It starts acting as a packaging format for agent capability.

Notice the mirror image with Claude Ship. Ship goes only to Team and Enterprise. Skills over MCP switches on by default for individual plans. Anthropic's two launches this week landed at opposite ends of its own customer base. And on by default is a distribution choice. It isn't evidence of demand.

Now the ecosystem number, with a caveat on its source. These are Anthropic's figures, as relayed by the tech site Sulat, not a post from Anthropic that we could read directly. Monthly downloads of the MCP software development kit have reached seven hundred million. That's up from one hundred million at the start of this year, a sevenfold rise. It's a real ecosystem-scale signal. But downloads count package installs, including ones pulled automatically by build pipelines. They are not active servers, active users, or production deployments. A sevenfold rise in installs doesn't mean seven times as many agents doing real work.

The second-order effect is contingent, and it's our inference. If skills become portable packages that other MCP-supporting vendors adopt too, custom integration code loses value. The packaged skill becomes the thing vendors compete to distribute. Nothing in the record confirms that cross-vendor adoption yet. So treat it as a thing to watch, not a conclusion.

To pull it together: the human checkpoint on AI agents is moving from a person to a policy, and agent capability is becoming a package. Three things are worth tracking from here. First, whether Claude Approvals leaves beta with a published price. Second, whether the excluded regulated configurations ever get access. Third, whether any vendor outside Anthropic adopts skills over MCP. That would tell us whether this becomes a real standard or stays a one-company feature.
