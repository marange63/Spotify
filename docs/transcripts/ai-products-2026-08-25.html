AI Products & Applications

Transcript · August 25, 2026

Good morning. It's August 25th, and here's what's new in AI products.

For most of this week, the story in this briefing has been permission. Who, or what, is actually allowed to act. This week one company answered that question twice. Both times the answer was: not the human.

Start with Anthropic. On August 21st it upgraded Claude Security, its automated code-vulnerability scanner, to run on Claude Mythos 5. Mythos 5 is its most restricted model, and a cyber-specialized one. Until last week it could not be called through the API, and it had no public model identifier. Reporting on the announcement describes it as reserved for a small group of partners selected through Project Glasswing, the program Anthropic runs together with the US government. As of the 21st, in that same account, its power steps outside that fence and becomes available to every Enterprise plan customer, with no one needing access to the model itself. That last clause is the one that matters. The model is now reachable. It is still not accessible.

Here is what a customer actually gets. Claude Security connects to a GitHub repository. It traces how data moves across files and git history. It returns findings tagged with a vulnerability category, a severity rating, and a suggested patch, pushed into Slack or Jira, or exported as a file. What nobody gets is a prompt box in front of Mythos 5.

That design choice is deliberate, and Anthropic says so in the announcement. The riskiest behavior, it writes, occurs when a user has direct access to a model, where a malicious actor can try to steer it toward harmful uses. But if users can only receive specific outputs, such as a patch for a vulnerability or a security alert, that risk is much lower. Take that argument seriously, because it is doing two jobs at once. It is a safety argument, and it is also a distribution strategy and a moat. There is no API and no public model identifier, so nobody outside Anthropic can build on Mythos 5 either. The constrained wrapper is the only way this capability reaches a mainstream enterprise buyer, and the only way it reaches anyone at all.

Now run the replace-versus-augment test. This is not a faster step bolted onto an existing security workflow. It is built to substitute for a whole product category: the static-analysis scanner market held today by Snyk, Veracode, and GitHub's own code scanning. That read is an inference from the product's shape. Anthropic has not claimed it.

Now the caveats, and they are real. Claude Security is in public beta, and Enterprise plan only. Not Pro, not Max, not Team. On price, Anthropic's announcement says scans are billed as standard token usage under your existing plan, with no separate add-on. That sounds friendly, and it is also unbudgetable. Incumbent scanners sell on per-developer or per-repository pricing a security chief can put in a spreadsheet. Frontier-model scanning bills against consumption nobody has sized in public. Which way that resolves decides whether this is a category replacement or a premium add-on.

More important than the price is the evidence, because there isn't any. Anthropic has published no performance data for this product at all. No detection rate. No false-positive rate. No count of vulnerabilities found. No comparison against any incumbent scanner. And because the model ships only as a product output, no third party can benchmark it either. There is nothing to point a test at.

The launch did come with a thirty-five million dollar fund, paid in Claude credits rather than cash. It is aimed at organizations working to patch vulnerabilities in open-source projects and to automate scanning and patching. But Anthropic says it is starting with a small number of larger, pilot grants. No recipient has been named yet. So there is no adoption story there either. Here is the plain summary of the lead. A category-replacement product shipped this week with essentially no evidence attached, from a vendor whose safety case and business case point in exactly the same direction.

Withholding the model is one way to take the human out of the loop. Taking the human out of the approval step is the other. Anthropic shipped that one too, eleven days earlier.

On August 14th, new Claude Code sessions on Pro, Max, and Team plans began running in auto mode by default. Claude Code is Anthropic's coding agent. Auto mode is a classifier that decides, in real time, whether a command the agent wants to run is safe. It replaces the setup where a person approved each risky action by hand. Anthropic backs the switch with a controlled study of 1,053 paid testers, published on its own blog.

The head-to-head is the figure to hold onto. Auto mode blocked 800 commands that a human tester had already approved. Going the other way, humans blocked six commands that auto mode allowed. On the raw catch rate, the testers flagged the dangerous command 13.6 percent of the time, against 89 percent for the classifier. So on Anthropic's own numbers, the human reviewer is the weaker safety control, not the stronger one. If that holds up, it undercuts a large body of enterprise AI governance built on the assumption that mandatory human sign-off is the safer default.

But look at who got the new default and who did not. Anthropic's own list names Pro, Max, and Team. Enterprise and API are not on it. They stay opt-in. If AI-mediated review were unambiguously safer, you would expect the customers with the strictest audit obligations to get it first, not last. The likelier read is that contractual sign-off requirements, not the study, are setting where the human stays in the loop. And name the underlying problem plainly. This is a vendor running a single controlled scenario on its own product, publishing the result itself, with no production incident data to check it against.

There is a clean test coming. Watch whether Cursor, GitHub Copilot's agent mode, and Replit flip their own default permission models over the next few weeks. Watch, too, whether Anthropic's Enterprise carve-out survives contact with its customers' contracts. Those two answers separate evidence changing practice from a vendor changing a default.

If people are being removed as the check at the model layer, and at the command-approval layer, then what is left to constrain agents is the protocol they speak to each other. Control of that protocol just moved out of any single vendor's hands. On August 20th, by the reporting on the transfer, Google's Agent2Agent protocol formally joined Anthropic's Model Context Protocol under one governing body. That body is the Linux Foundation-directed Agentic AI Foundation. The division of labor is clean. MCP standardizes how an agent connects to tools and data. A2A standardizes how independent agents talk to each other. Or as one report framed it, where A2A fits is at the collaborative edge, and where MCP fits is at the tool integration edge.

The scale of the buy-in is what makes this notable. By that same report's count, the foundation grew from 49 founding members to more than 250 in less than a year. Anthropic, Google, Microsoft, OpenAI, AWS, Bloomberg, Block, and Cloudflare have all signed on to the same governance model. This is also the third straight day this show has watched agent plumbing move to a neutral body. On Sunday it was MCP's own steering group admitting agents still cannot prove their identity. On Monday it was GitHub's Agent Plugins format, governed independently of any single vendor. Now both major labs' protocols sit under one roof.

Keep the limits in view. This is a governance signal, not a shipped capability. No production traffic figures under the unified foundation have been published. No enterprise has cited the combined stack in a live deployment. And shared governance cuts both ways. The identity gap that MCP's own roadmap admitted to last weekend now needs committee agreement to fix, rather than one company's roadmap. Agent autonomy is being handed out faster than the body governing how agents authenticate can move.

So here is the shape of the week. Two products from the same company removed human discretion from the loop. One denies access to the model and sells only its output. The other replaces manual approval with a classifier. Both were measured, where they were measured at all, by the company selling them. That company has now led this briefing twice in five days. The one part of this stack getting more oversight rather than less is the part no single vendor owns.
