Good morning. It's Wednesday, October 28th, and this is your AI products briefing.

One disclosure up front: Anthropic makes the model behind this show. Two of today's items touch Anthropic. Claude Code is one of the agents named in a third-party security release, and we'll close with a change to the Claude API.

Here's the spine for today. Coding agents are moving from writing code to running it. They now answer production alerts, patch live vulnerabilities, and ship as deployable services. And across every vendor doing this, the product decision that matters isn't the model underneath. It's where they place the human approval gate before the agent can touch production.

Start with the lead. On-call agents reached general availability from two separate vendors over the past two weeks. Cognition launched Devin Oncall on October 15th. It investigates alerts and bug reports, and helps teams diagnose and resolve production incidents. Replit followed with its own Monitoring Agent, documented in an October 23rd changelog. It reads an app's production logs and metrics, then attempts and validates a fix. Two independent vendors shipping overlapping capability within days makes this a category, not a single launch.

My inference is that this also means a different budget line. These agents compete for on-call and remediation labor, not developer seats.

Now the numbers, and the denominators matter. Cognition says Devin Oncall achieved, quote, "100% end-to-end success" on a benchmark called SREGym. Specifically, it's a seventeen-fault subset that Cognition's chart labels SREGym-Lite. The comparison set is other AI agents on that benchmark's public leaderboard. It is not human responders, and it is not a commercial incident-response tool. And it's Cognition running its own evaluation. That's a much narrower claim than "handles incidents better than your on-call team."

Cognition also relays a customer figure from AngelList. AngelList reports that Devin correctly identifies root causes three and a half times more often than its in-house harness. It also says Devin handled fifty percent of incidents end-to-end on its own. Read that fifty percent the other way: half of those incidents still needed a human. And neither vendor has published a false-fix rate. That's the number that actually matters once an agent can change code running in production.

The tell is in the defaults. Replit's changelog says the agent triages alerts in the background only after a user turns on monitoring alerts and auto-fix. It's opt-in, not default. Shipping a fix straight to production takes a further, separate step. In the changelog's words: "To publish validated fixes automatically, also enable the experimental Auto-republish setting. Otherwise, review and publish fixes yourself." Replit itself labels automatic production writes experimental. That tells you more about where reliability stands than any benchmark score.

There's a competing reading worth voicing. This may be triage automation marketed as autonomous SRE. Investigation and root-cause drafts are the valuable, low-risk part. The autonomous fix is still opt-in and unmeasured. My further inference: if these agents work, observability tools start to look like data feeds for agents rather than dashboards for humans. So the takeaway: the agent is on the pager now, but every vendor still routes the live production write through a gate a human must flip first.

If the agent can answer the alert, the next step is fixing the vulnerability before there's an alert at all. That's what Cognition did on October 24th. It open-sourced a set of agent skills that patch specific, named critical flaws. One covers an unauthenticated remote-code-execution family in PHP. Another covers a Node.js vulnerability from Node's own October security release. The third targets a GitLab flaw rated CVSS 10.0, the maximum severity, an unauthenticated remote code execution in self-managed GitLab. Each skill runs a read-only inventory first. Each requires explicit approval before touching a repository, and it proposes changes as pull requests rather than merging. No remediation success rate has been published.

The notable part is portability. Cognition and MarkTechPost say the skills work not just with Devin, but with Claude Code, Codex, and Cursor. Last Friday we raised the question of who reviews third-party agent skills. On Saturday, Anthropic was claiming that more than seventy platforms had integrated the skills format. This is what that portability looks like in practice, and it makes the security question live.

Here's why. If a skill runs with the invoking agent's permissions across four platforms, a compromised skill repository becomes a new supply-chain surface. No neutral review process for these skills has been described. The approval gate and read-only inventory are real mitigations. But they're the vendor's own design, not an independent audit. There's also a more cynical reading, and it's my inference. Giving away cross-agent skills is how Cognition makes Devin the reference implementation others must match. So: portable security skills are now a shipped product, and the trust question around them is no longer hypothetical.

Those are agents other companies build and ship to you. Cursor now lets teams build and ship their own. Cursor's Agent SDK went generally available on October 20th. Developers define an agent as a folder of code, test it, and deploy it with one command. Per Cursor's changelog, quote, "The agent-sdk deploy command builds the agent, assigns it a URL, and runs it on Cursor's infrastructure." That last clause matters. As documented, the agent runs on Cursor's own infrastructure. So what looks like flexibility also keeps that compute and spend on Cursor's platform.

Cursor paired the SDK with its Origin marketplace. It integrates more than twenty partner apps for deployment, CI, code review, security, and monitoring, and it's open to public submissions. That turns the coding tool into a distribution shelf that devtools vendors compete to sit on. No usage or customer figures were disclosed for either. Last Friday, covering Cursor's beta Environments API, we inferred the buyer was shifting toward platform teams. The SDK strengthens that read. The agent itself is becoming a deployable service, owned by a platform team rather than a developer with an IDE.

All of that assumes you're allowed to run the agent in the first place. For regulated institutions, the answer is to move the whole runtime inside their own walls. Perplexity announced a partnership with the startup Valarian on October 20th. It lets Perplexity's Computer agent run inside a customer's own controlled infrastructure, including air-gapped networks. Valarian's ACRA platform, in the reporting's words, "runs Computer on infrastructure the institution controls and enforces the access and network policies governing that work."

That answers a gap we flagged on Saturday. Perplexity's local Mac mode had a per-user toggle, but no enforceable institutional control. Perplexity is explicitly targeting finance, government, and defense. But no named customer or deployment has been disclosed, so this is a capability announcement, not a proven win. Valarian raised fifty million dollars in July. That shows investors see a category, not that this product has traction. And one question the available material doesn't answer: how much of an agent's usefulness survives inside a closed network, without live browsing or connected apps. So for the regulated buyer, the fix isn't a more trustworthy agent. It's moving where the agent runs.

One brief item to close the spine. On October 21st, Anthropic shipped a new dated Claude API version. The version it supersedes dates to June 2023. According to a developer write-up of the migration guide, the new version returns, quote, "a 400 error, even at the parameter's default value," for any request that sets temperature, top_p, or top_k. Many production agents and eval harnesses lean on those settings for repeatable output. The reported guidance is to use prompting instead, and to keep any low-temperature request pinned to the 2023 version, which is not deprecated. So nothing breaks unless a team upgrades. But my read on the direction: teams that need determinism will either stay pinned or look elsewhere.

Put it together. Agents now operate and patch software after it ships, not just write it beforehand. And in every one of today's launches, the real product decision is where the vendor draws the approval line before an irreversible write. Three things to watch. Whether anyone publishes a false-fix rate for an on-call agent. Whether Replit's Auto-republish graduates out of experimental. And whether Valarian or Perplexity names a real deployed customer.
