Good morning, it's July 29th, 2026, and this is your Cautious Optimism briefing on AI products. This week the contest among AI products stopped being about what a model can do and started being about whether you can actually run it in production. Three stories this week trace that same line: a protocol that just removed its biggest deployment blocker, a CRM incumbent betting its own customer data beats a standalone agent startup, and a price cut that makes the resulting workloads affordable to run all day.

We flagged on the 27th that the Model Context Protocol was finalizing a breaking rewrite due to land the next day. It landed. The 2026-07-28 specification is the largest change to MCP since it launched, and the headline shift — moving from a stateful, session-based protocol to a stateless request and response model — is something we already walked through. What's new is what came with it. MCP's own spec authors describe the change plainly: MCP is transforming from a bidirectional stateful protocol into a request and response stateless one. Practically, that means a remote MCP server no longer needs the sticky routing or shared session store that every production deployment had to build around just to keep a conversation pinned to the right machine. That requirement is exactly what stood between a working demo and a service that can sit behind an ordinary load balancer like any other piece of web infrastructure. Removing it doesn't just simplify code, it removes an operations team's excuse for keeping an agent in pilot instead of production.

The spec also rewrites authorization, and this part is squarely aimed at enterprises letting tool-using agents near real internal systems. Authorization servers should now return an issuer parameter per an internet standard called RFC 9207, and clients must validate it before redeeming a code. Client credentials are bound to whichever authorization server minted them, with no reuse across servers. That closes a class of token-replay risk that matters a great deal once an agent has standing access to a company's databases rather than a sandboxed demo account.

Third, the protocol formalized how it evolves at all. A new extensions framework is now locked in, with a capability called Tasks joining two extensions already in place, MCP Apps and Enterprise Managed Authorization. Tasks moves long-running tool calls out of the experimental core and into a proper extension built on polling instead of a blocking call: a client can check on a task, push it new input mid-run, or cancel it, rather than sitting on a single request until the tool finishes. That is the specific plumbing an agent needs to kick off a job that takes minutes or hours and check back later, which is exactly the kind of workload enterprises are trying to move off pilot infrastructure. All four Tier 1 SDKs — TypeScript, Python, Go and C sharp — shipped support for the new spec on release day, so developers aren't waiting on tooling to catch up.

Two caveats worth holding onto. The performance and cost benefits of going stateless are claims from the protocol's own maintainers, not yet measured independently in production. And this is a genuinely breaking change: existing deployments built around sticky sessions need real server and client updates. The spec does give them a defined runway — a formal deprecation policy with a twelve-month minimum window before specific older features are actually removed — so this is a planned migration, not a cliff. It's also worth being precise about the governance story here: MCP's multi-vendor stewardship, under the Linux Foundation's Agentic AI Foundation with eight platinum members spanning Anthropic, OpenAI, Google, Amazon, Microsoft, Block, Bloomberg and Cloudflare, isn't new this week. Anthropic donated the protocol into that foundation back in December. What's new is that this is the first major spec revision to ship visibly under that structure, which is exactly what makes MCP feel more like a durable, boring standard — the way HTTP or gRPC are — rather than one company's project that others merely support.

One more consequence worth flagging, because it tells you who this quietly hurts. A whole tier of gateway and hosting vendors — think AWS's AgentCore Gateway — sold their value as managing exactly the session state that MCP just deleted. In the short run, the messy cutover hands them a burst of business, since companies will pay for help migrating old-spec servers to new. But once the migration is done, the hard thing they were charging to manage no longer exists, and they have to move up-stack to justify the seat. Commoditizing your own hard part is the price of admission to becoming boring, standard infrastructure.

If MCP is removing the plumbing friction for people building agents, HubSpot is removing the build friction for people who already own the data. HubSpot opened Agent Hub and Agent Builder in public beta on July 23rd for every Professional and Enterprise customer. Agent Hub gives sales, marketing and service teams one console to see and manage every agent running across the business. Agent Builder is the more interesting bet: a low-code, natural-language tool, built on HubSpot's Breeze Assistant, that lets a non-technical user build and customize an agent directly against existing CRM data, with no separate field mapping required. That's the wager underneath it — that owning the customer data natively lets an incumbent out-build a standalone agent-orchestration startup that has to integrate with that data from the outside. HubSpot's one cited proof point is a customer called Ignite Reading, which used a custom agent to cut a task from fifteen to twenty minutes per school district down to seconds, saving more than 350 hours a year. Treat that as a demonstration of the mechanism, not evidence of typical results — it's a single, vendor-selected case study, and this is a public beta, not a general release. Watch for whether Salesforce, ServiceNow and Workday ship the same console-plus-builder pairing, because if data gravity really is the moat, every incumbent with a proprietary dataset has the same incentive to build it. The flip side for buyers is lock-in: an agent built on HubSpot's data doesn't travel to a competing CRM.

Closing the loop on economics, Anthropic's Claude Sonnet 5 launched at an introductory rate of two dollars per million input tokens and ten dollars per million output tokens, through August 31st, rising to a standard three and fifteen after that. Anthropic says Sonnet 5's performance now sits close to that of the prior Opus 4.8 tier, at Sonnet-tier pricing. Treat the underlying benchmark claims as Anthropic's own internal evaluations rather than independently verified, and remember this rate is a limited-time promotion, not the permanent price. But directionally, it's the piece that makes the other two stories pay off: cheaper capable tokens are what make it economical to actually run the longer, multi-step production workloads that a stateless MCP and a native CRM agent builder now make possible to deploy in the first place.

So the pattern across all three: the model layer keeps getting cheaper and more commoditized, while the real fight has moved to deployment, governance and data ownership. Capability was never really the scarce thing this year — the ability to run it reliably, cheaply and safely in production was. That's it for today's briefing.
