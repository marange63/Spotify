Good morning. It's September 27th, 2026, and this is your AI products briefing.

This week's agent headlines were mostly about price. But the terms that decide what a builder can actually do sit below the headline number. Google just shipped a clean example.

Google has turned Antigravity, its autonomous coding agent, into a managed agent inside the Gemini API. Google's documentation describes it as a general-purpose managed agent that "plans, reasons, runs code, manages files, and searches the web inside a secure, isolated Linux sandbox hosted by Google." That's the mechanism worth sitting with. A developer used to assemble that stack alone: a sandbox, a way to wire in files and credentials, and an agent loop that plans and retries. Now it's an API call. Google's docs say the new preview, antigravity-preview-09-2026, is built on Gemini 3.8 Flash. They also say it uses the same harness as Google's standalone Antigravity IDE. So this isn't a stripped-down cousin of Google's own coding tool. It's the same engine, rented out. The September release also upgrades that harness, in Google's words, with "improved prompt caching, native code search tools, and efficient line-range file editing." And Google's docs now list new Files and Credentials APIs alongside it.

Consider who that squeezes. A whole layer of agent startups built exactly this: hosted sandboxes, custom harnesses, and credential plumbing. When the model vendor ships that layer as a primitive, a thin agent wrapper loses much of its reason to exist. Its moat has to come from somewhere else, such as proprietary data, a vertical workflow, or distribution. Note what this replaces and what it doesn't. It replaces infrastructure, not the developer. The builder still decides what the agent does. They just no longer own the machinery it runs on.

Here's the part that doesn't show up in the headline. The listed input window is over a million tokens, 1,048,576 to be exact. But Google's own spec says that window is compacted at roughly 135,000 tokens. So the working window an agent actually reasons over is closer to an eighth of the headline figure. There are two honest readings of that. One is that compaction is a reliability choice. It keeps a long-running agent focused instead of drowning it in its own history. The other is that it's a hidden ceiling dressed up as a million-token feature. Both can be true at once. Either way, builders should plan around the smaller number.

On price, Google is more forthcoming than you might expect for a preview. Its documentation says, "Pricing follows a pay-as-you-go model based on the underlying Gemini model tokens and the tools the agent uses." Free-tier projects get, in Google's words, "a free rate limit and usage quota." So this is metered on tokens and tool calls, not a black box. What's missing is a per-session or per-sandbox-hour figure. The pricing mechanism is public. The total cost of a long agent run is not yet predictable.

Then there's the clock. Google's docs say the prior preview, antigravity-preview-05-2026, shuts down on October 5th. That version launched in May, on the older Gemini 3.5 Flash. So it will have lived roughly four and a half months. As of this morning, anyone still on it has eight days. Previews carry short support windows by design, and that's the fair reading here. This isn't a broken promise.

But notice what migration actually means. The brand stays the same, while the underlying model moves from Gemini 3.5 Flash to 3.8 Flash. A team that tuned its prompts against the May agent inherits a different model, not just a better harness. And this fits a pattern this show has tracked all week. OpenAI's Sora API ended on September 24th with no successor video API. Perplexity's Sonar API retires today, after a roughly forty-five-day migration window. The vendor sets the calendar. If you build on rented agent infrastructure, you also rent its expiration date.

So the takeaway on Google. This materially lowers the cost of building a coding or research agent, because sandboxing and orchestration become Google's problem, not yours. But the effective product is smaller and more provisional than the spec sheet implies, on context and on continuity.

Google isn't the only vendor whose real limit sits below the headline. xAI's Grok 4.7 shows the same dynamic, through price instead of compaction. On Wednesday, this show set Grok 4.7's pricing aside, because there was no primary xAI source. xAI's release notes now carry it. The model has a 500,000-token context window, with text and image input and text-only output. Under 200,000 prompt tokens, xAI charges two dollars per million input tokens, fifty cents cached, and six dollars for output. Above 200,000, every one of those rates doubles. That line is exactly where the late turns of a long agent session land. So a long-running agent pays double once its prompts cross it. The 500,000-token window is real. Using the far end of it simply costs twice as much.

The timing matters for how to read that price. Grok 4.7 shipped on September 21st. That's a day before Anthropic released Opus 5.5 and OpenAI cut its prices, both on the 22nd. So xAI wasn't refusing to match its rivals. Its price was set first, and the cuts landed around it afterward. For a list-price anchor, Anthropic's Opus 5.5 costs four dollars per million input tokens and twenty for output. Below the threshold, Grok 4.7 lists at half that input rate. Above it, Grok's input matches Opus at four dollars, while its output stays cheaper. That's a list-price comparison only. There's no independent benchmark in hand to say which delivers more work per dollar.

The point for builders is structural. Harness design means how you compact context, cache it, or split work across subagents. That used to be mainly a quality decision. On xAI's platform, past a fixed threshold, it's now a direct cost decision. On Google's, compaction decides what the agent can still see. Either way, the harness, not the spec sheet, sets the effective product.

If the harness itself is becoming rentable infrastructure, the scarce thing shifts to distribution: whose surface the agent lives on. That's the frame for Perplexity's latest move. Perplexity says its Computer agent will come "pre-installed on HP ZBook Ultra G3a," a workstation laptop that Perplexity says ships in October. That puts Perplexity's agent on the machine by default, with no download required. It contests exactly the default-assistant position Microsoft is reinforcing with the Copilot relaunch this show covered yesterday.

Keep it in proportion, though. This is one workstation model, not a fleet-wide Windows deal. Perplexity says more HP devices will follow, but gives no date. And the announcement is from September 15th, so it's older news now reaching a ship date. Treat it as a data point in the distribution fight, not a breakthrough.

Put the three together and one shape emerges. The agent harness, sandbox and all, is turning into infrastructure you rent rather than build. That's good news for anyone building a coding or research agent, because the assembly cost drops. But the effective product is smaller than the spec sheet promises, once you account for compaction and pricing thresholds. It's also more temporary than it looks, once you account for how fast previews get retired. Two numbers would settle how much this matters. One is a published per-session cost for Google's managed agent. The other is a real session cost for a coding agent that crosses Grok's 200,000-token line. Until those exist, budget for the smaller, pricier, shorter-lived version of what's advertised.
