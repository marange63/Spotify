Good morning, this is Cautious Optimism Briefings, enterprise technology for Tuesday, September 29th, 2026.

No big platform earnings landed this stretch, so today is one story in two parts. All week, this beat has tracked the agent-governance question through vendor surveys. Now it is being answered a different way. Incumbents are building the answer into their defaults and their bundles.

Start with GitHub. On September 24th, GitHub's changelog announced that generally available Copilot features will switch on by default for every Copilot Business and Enterprise customer. The policy takes effect October 22nd. It covers three things: the features on an enterprise's "Features and clients" page, the Copilot Code Review policy, and, notably, the MCP servers in Copilot policy. Administrators get an "AI Controls" page with three choices: enabled, disabled, or let organizations decide. GitHub is explicit that choices already made are preserved. In its words, "If you've explicitly enabled or disabled a feature, we won't override that choice." But if you never touched the setting, October 22nd flips it on for you. So the governance decision moves from opt-in to opt-out. The burden of even knowing there was a decision to make now sits with enterprise IT.

Underneath that switch, GitHub has also changed what a seat actually buys. GitHub has moved every Copilot plan to usage-based billing. For June, July and August, it cushioned that move with promotional included usage. On September 1st, the promotion rolled off. An Enterprise seat's included usage fell from seven thousand credits to thirty-nine hundred. According to the pricing-analysis firm CloudZero, that's a 44 percent cut for Enterprise pools and a 37 percent cut for Business pools. CloudZero notes that a credit is a cent. So an Enterprise seat went from seventy dollars of included usage to thirty-nine. The seat price did not move. What the seat buys did.

This is the drift this beat flagged on Thursday the 24th. Back then, new Copilot Business licenses sold through Microsoft's partner channel were set to default to usage-based billing from November 2nd. Saturday's Throughline put the broader pattern as the meter overtaking the seat. GitHub has now pushed that meter deeper, into its own core developer product.

There are three ways to read it. The first is a stealth price increase, since the same list price now buys meaningfully less usage. The second is that the exposure is narrower than it looks. Explicit admin choices are preserved, so the default only binds enterprises that never set a policy. The third is an engagement play ahead of renewals, pushing active usage per paid seat rather than squeezing revenue per seat. And the revenue case has its own condition. A smaller pool only lifts realized revenue per seat if heavy users actually pay overages. If they get throttled, or shift to cheaper models, the pool cut saves GitHub compute rather than earning it revenue. We have no opt-out data and no overage figures to settle any of this. What we do know is the shape of the trade. The seat stays the same price, what it buys shrinks, and the default decides who notices.

Now the governance side of that same switch. Turning MCP servers on by default matters beyond billing, because MCP is how an agent reaches tools and data. That brings back a number this beat reported on the 24th. A Guild.ai survey found that only 31 percent of organizations can immediately stop a malfunctioning agent with an automated kill switch. Guild sells agent-governance tooling and published no methodology, so treat that as directional.

Here we need to be precise about what GitHub has and hasn't said. Back in August, GitHub added a separate enterprise MCP allowlist. It has two settings. "Allow all" means any MCP server can be used. "Registry only" means only approved servers can run. But GitHub's documentation doesn't say which of those an enterprise gets if it never configured the allowlist. So nobody can honestly claim that on October 22nd, any agent can reach anything. The narrower point is the certain one. Enterprise IT now has two controls to check, not one, on a deadline, for a surface that is expanding. That review work lands on platform engineering and application security teams, not on GitHub. So the agent's reach is growing by default faster than the brake is being switched on by default.

That sets up the other half of today's story, which is the closest thing yet to an answer to that 31 percent number. On Monday, at Okta's Oktane conference, ServiceNow expanded its AI Control Tower around five functions: discover, observe, govern, secure, and measure. The system maps AI agents to the business processes that depend on them. And it folds in technology from the identity-security company Veza to adjust agents' excessive permissions.

ServiceNow's vice president of AI Platform Security, Bhakti Pitre, put the philosophy directly. Quote: "I love the term, but I also encourage everybody to think about that 'kill switch' is not just a button. It's not on and off." In other words, the binary stop button that Guild's survey measured is, in ServiceNow's telling, the wrong unit of governance. What ServiceNow is selling instead is graduated control, set at the level of permissions. That's ServiceNow's framing, not an industry standard. But if buyers adopt it, the 31 percent kill-switch statistic starts to look like the wrong scoreboard.

Grade this the way you'd grade any conference announcement: as capability, not production usage. ServiceNow disclosed no customer names, no adoption counts, no pricing, and no revenue tied to Control Tower. Graduated containment may partly be existing permissioning and incident-response workflow relabeled under an AI banner. The process mapping is the substantive claim. It's only as good as the customer's own process data, and that data is often incomplete. And there is an obvious tension in a platform that builds agents also selling the brake that governs them. This beat has discounted vendor-sponsored surveys for grading their own homework. The same concern applies to vendor-sold governance.

The Veza piece carries its own second-order effect. When a suite vendor right-sizes agent permissions using an identity vendor's technology, identity moves into the agent-rollout budget. Permissions stop being a back-office hygiene item and become agent infrastructure. That's a demand driver for identity vendors tied to how fast agents deploy. No revenue figure attaches to it yet, so treat it as a direction, not a data point.

Now step back to the competitive picture. On Saturday, this beat flagged a structural risk. Agent-building platforms could bundle governance into their suites and cap what standalone governance tools can charge. The example then was Dataiku's Agent Management, with general availability planned for October. Two days later, ServiceNow's expanded Control Tower looks like that bundling move in practice. That's an inference. There is no pricing or revenue evidence yet to prove standalone pricing has been capped.

Pair it with GitHub and the squeeze runs from two directions. GitHub, one incumbent, sets the defaults that widen what agents can touch. ServiceNow, another incumbent, sells a graduated brake as a suite feature, and pulls identity technology in along the way. Both push real work onto enterprise IT and security teams rather than absorbing it themselves. And both put the standalone governance players on the spot. A Dataiku, or Guild.ai itself, now has to prove it adds something beyond controls the customer already gets in the bundle. For standalone vendors, the pitch shifts from "you have no brake" to "your suite's brake doesn't cover everything."

So what would actually settle this? On the GitHub side, we'd want opt-out numbers and evidence of overage revenue once October 22nd passes. That tells us whether this is monetization or engagement. We'd also want GitHub to state the allowlist's default, which tells us how big the security review really is. On the ServiceNow side, we'd want customer counts and pricing for Control Tower, to know whether graduated governance is being bought or just announced. And when Dataiku reaches general availability in October, its first customer numbers will show whether a standalone brake can still win deals. Until then, the honest read is that the agent surface is expanding by default, and the tools to govern it are still mostly promises.
