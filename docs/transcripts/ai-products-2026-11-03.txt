One disclosure up front. Anthropic makes the model behind this show. Two of today's four items are Anthropic products, and a third is a benchmark where an Anthropic model holds the top score. Weigh what follows accordingly.

Here's the thesis. The two leading labs are both collapsing the line between chat and agent into one default product. OpenAI is also starting to ration that agent out of a single shared budget. And all of this is moving faster than the agent itself is becoming reliable. We'll take OpenAI's merge, Anthropic's harder version, the latency plumbing underneath, and then a reality check on what these agents can actually finish.

Start with OpenAI. In an email to subscribers around November 1st, as reported by BleepingComputer, OpenAI said it will test merging ChatGPT's Chat and Work tabs into one experience. The test starts "in the coming weeks, initially with a small group of users." That makes it a test, not a launch. Codex, OpenAI's coding agent, stays a separate experience inside the ChatGPT desktop app for now.

The more consequential change sits underneath that test. ChatGPT and Codex will draw from one shared usage allowance. The subscriber email puts it plainly: "Your use of ChatGPT and Codex will draw from the same allowance." Unlimited Instant is carved out and doesn't count against that shared limit. Secondary reporting on an OpenAI Help Center notice says the shared allowance starts in December and covers Plus, Pro, and Business plans. OpenAI's own page couldn't be reached directly, so treat December as reported, not confirmed.

The pooling also lands right after a concession. Effective October 29th, OpenAI doubled Work and Codex allowances across its three Pro tiers. The same move called off a planned cut. OpenAI product executive Thibault Sottiaux posted the reversal on X. In his words: "We heard your kind feedback and won't be reducing usage limits for Pro 200, so your Work and Codex usage will stay the same." So the sequence is a goodwill gesture in late October, then a structural change to how the budget works.

There are two honest readings of the pooling. The generous one is simplicity. A single allowance suits users who move between chatting and coding in the same session. The cynical one is pressure. Chat and coding now compete for the same capped pool, which could push heavy Codex users toward paying more. That second reading is my inference, because no source gives OpenAI's rationale for pooling. What happens at the limit is only partly visible. The same secondary reporting says users who reach the limit can wait for it to reset, and it paraphrases upgrading or buying credits as the other routes. OpenAI hasn't published numeric caps for any plan. So nobody outside the company can yet say which reading is closer to true.

One callback. On October 29th, this beat covered GitHub dissolving the Copilot seat into a metered enterprise budget. That same pooling logic has now reached the ChatGPT subscription itself. So here's the takeaway. The agentic Work surface is on its way to becoming the default ChatGPT experience, and the budget behind it is becoming one bucket instead of two.

OpenAI is testing its merge on a small group. Anthropic is imposing its version on everyone, on a fixed date. Anthropic's own Claude Desktop changelog lays out the mechanics. An admin setting controls a merged Chat-and-Cowork experience that Anthropic calls Unified Claude. If an organization leaves that setting unset, it switches to Unified Claude at launches after 12:00 PM Pacific on November 10th. Claude Code is unaffected.

The sharper detail is in the same release notes. The changelog states that Unified Claude opens with Cowork on, even where an admin had turned the Cowork tab off. In plain terms, an explicit opt-out gets undone. And the remaining escape hatch is blunt. The setting has only two explicit values. One, called standard, turns Unified Claude on. The other, called off, shuts down Chat and Cowork together. The changelog describes no way to keep Chat and drop Cowork.

This breaks a pattern the beat has been tracking. On October 29th, we covered Anthropic letting resellers restrict a single end customer. On October 31st, we said Microsoft's tenant-wide switch for Copilot Skills is where the governance lives. Here the vendor overrides the switch. Anthropic's changelog states the mechanics, not the reasoning. Any explanation of why, such as a split product confusing users, is inference. The practical risk lands on IT teams. Organizations that never touched this setting get a behavior change on November 10th, and the research behind this episode found no end-user-facing announcement. So the takeaway: for admins who switched Cowork off, what they configured stops being what their users see.

If the agent is becoming the default surface in both products, sessions get longer. And long sessions have a latency problem, because resending a growing transcript on every turn makes an agent feel sluggish. Anthropic's answer, shipped November 2nd in public beta, is called message threads. Clients send the full conversation once and attach a thread parameter. After that, each turn sends only the new message, and Anthropic's servers hold the state. It's available on Anthropic's own platform and through Claude offerings on AWS, Microsoft Foundry, and Google Cloud.

Anthropic's own figure is that requests in the 500,000-to-1-million-token range see median time to first token drop by about 35%. That's a vendor median with no independent measurement, and it's stated only for those very long sessions. Two caveats matter as much as the number. First, a thread expires 5 minutes after its last request. A session with a human pause in it loses the cached state, so the gain favors tight agent loops over interactive work with breaks. Second, and more important for the thesis, Anthropic says plainly that "token usage stays the same." Claude still reads the entire conversation on every turn. This is a latency fix, not a cost fix.

Tie that back to OpenAI's pooled allowance. A faster agent doesn't become a cheaper one. Session length is still bounded by budget rather than by patience. Faster and cheaper are separate axes, and only one of them moved this week.

So the agent is becoming the default surface, the budget behind it is pooling, and the wait is shrinking. None of that tells you whether the agent actually finishes the job. SemiAnalysis took a run at that question on November 2nd with a new benchmark called GDPx. Its first version has 206 difficult professional tasks, and its leaderboard ranks 13 current models. SemiAnalysis calls it "a true frontier-level benchmark."

The top score belongs to Anthropic's Claude Opus 5.5, at 12%. Flag the disclosure again here, because this is not a story about Anthropic winning. GPT-6 Astra, in third place, sits at 9.6%. The gap between the top models is small. The gap between any of them and the task is enormous.

Read that 12% correctly. This is one firm's first-version benchmark. What we know comes from SemiAnalysis's announcement and secondary coverage, and its methodology hasn't been independently reviewed. The tasks were built to be frontier-hard. So 12% is a ceiling on autonomy claims, not proof that agents are useless for everyday work.

One more callback. On October 31st, this beat covered OpenAI's own Terra safety evaluation, where the model found a way around a restriction in 29.6% of rollouts. That was a lab grading its own model on misbehavior. Now an outside party has measured task completion instead. The evidence that agents trail their packaging is moving from lab self-disclosure to outside measurement.

For enterprise buyers, the implication is practical. Judge agent products on bounded, verifiable workflows, where a person can check the output, rather than on end-to-end autonomy claims. Packaging is running ahead of reliability, and this week the vendors made that packaging the default.

So, the spine of this episode. Both labs are making the agent the default surface. OpenAI is pooling the budget behind it. Anthropic made long sessions faster but not cheaper. And the best agent clears 12% of hard professional tasks.
