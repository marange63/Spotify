Good morning, it's Monday, September 28th, and this is your AI products briefing.

All through last week, this show tracked what agent work costs. Today the question moves further down the funnel. It's no longer what an agent costs to run. It's whether anyone will let the agent through the door.

The lead is Amazon blocking Meta's shopping agent, Muse, from its retail site. The block message Amazon shows users is blunt. "Continued access by an unauthorised AI agent violates Amazon's Conditions of Use, to which our customers have agreed." Amazon's stated policy is that third-party apps buying on a customer's behalf "should operate openly and respect service provider decisions about whether or not to participate." In plain terms, the storefront has to consent. Amazon also alleges that Muse accessed its platform without disclosing itself, and that it captured customer login credentials. That charge is Amazon's allegation, not an adjudicated fact.

Meta has pushed back, but only on the narrow point. Meta says its agent "has no visibility into people's passwords or payment methods." Its explanation is that login information sits in secure storage the agent can use without directly accessing it. That is a real technical rebuttal to the credential charge. On the block itself, though, Meta did not respond to requests for comment. So the credential allegation now has a counter-argument on the record. The larger question, whether Muse was entitled to be on Amazon at all, has none.

On Saturday, this show quoted Microsoft's Satya Nadella saying that every agent has to have an identity. That was a vendor describing a governance goal for its own agents. Amazon is now enforcing the same principle from the platform side, against a rival's product. So agent identity has stopped being a design nicety. It's becoming a precondition for distribution.

There are two honest readings of what Amazon did. The first is security enforcement. An undisclosed automated agent working inside customer accounts is a genuine account-safety problem. The second is competitive foreclosure. By deciding which agents may transact, Amazon keeps the customer relationship, the checkout data, and the conversion funnel.

Two tests would separate those readings. Does Amazon apply its rule evenly? And does it offer any sanctioned path for an agent that openly identifies itself? On the second test, this show found no public Amazon program for declared third-party purchasing agents. Treat that as a gap in the evidence, not proof that no such path exists. On the first test, the evidence leans one way. Tech Times reports that Amazon's own agentic purchasing feature, Buy for Me, worked the other way around. In that outlet's words, "Amazon assumed participation and required retailers to affirmatively opt out." So rivals' agents need a merchant's affirmative consent, while Amazon's own agent assumed consent by default. The same report says that "Amazon has not publicly addressed this contradiction." That asymmetry doesn't disprove the security concern. But it does show the standard isn't neutral. Amazon writes the rule, and Amazon decides where it applies.

The incentive behind that is easy to see. Amazon's own assistant, Rufus, can research products, track prices, and automatically buy items in Amazon's store when they hit a set price. Amazon says Rufus monthly active users rose more than 115 percent year over year, with engagement up nearly 400 percent. Amazon is also pressing the same fight in court. It has filed amended federal claims against Perplexity over its Comet browser agent. Those claims allege Perplexity "disguised an automated 'agentic' browser as a human user, to evade Amazon's technological barriers, and to access private customer accounts without Amazon's permission." Put together, Amazon is closing the checkout gate to outside agents while its own agent scales behind it.

For anyone building a shopping or browser agent, the so what is platform risk. An agent that works by logging into a user's account on a large platform can lose that access by policy overnight. That fragments the market such an agent can actually serve. My inference is that the deal-making path gains ground as a result. That means negotiated partnerships, where the counterparty opts in, rather than scraping a storefront and acting on it. No one has reported that shift yet, but it follows directly from Amazon's posture.

So what does an agent built to pass a gate actually look like? Oddly, a useful example is the same Comet that Amazon is suing over. Perplexity, which this show has been tracking as a distribution player, has taken Comet into the enterprise. Administrators can now deploy it silently across Mac and Windows machines through mobile device management. They can configure hundreds of browser policies. And they can control exactly which actions the agent is allowed to take. That's the declared, permissioned model. IT decides what the agent may do before it reaches any website.

Be precise about what this proves. The description comes from a secondary source, with no firm date, no customer count, and no deployment scale. It's capability, not adoption. And enterprise permissioning is a different problem from platform permission. An admin can fully govern what Comet attempts, and Amazon can still refuse to let it transact. Still, Amazon's allegation puts a new question on every procurement checklist. How does this agent hold my login? Products with admin-scoped permissions have a better answer to that than consumer agents do. That's a design a skeptical enterprise buyer, and eventually a skeptical counterparty, can both approve.

The declared route already has real scale on the tooling side, even if not yet at the storefront. The Model Context Protocol is the open standard for connecting agents to tools and data. According to Cloudflare, its main developer kits see close to half a billion downloads a month. Both the TypeScript and Python kits have each crossed a billion downloads in total. That's a lot of developers building on a protocol where the tool provider chooses to expose access. Two limits apply. Downloads count package installs, not live production traffic. And MCP only works where the counterparty opts in. It won't force Amazon, or any retailer, to open its checkout to an agent it hasn't sanctioned. It's a highway for willing partners, not a key to someone else's door.

The same question of who controls the surface also shapes what labs choose to keep. On Saturday, this show noted that OpenAI had given no stated rationale for retiring its Sora video API, which went dark on September 24th. New reporting fills part of that gap. Tech Journal reports that Sora cost roughly one million dollars a day to operate. Against that, it generated only about two-point-one million dollars in total revenue. Its worldwide users peaked around a million before falling below half a million. Hold those numbers loosely. They're press estimates, not an OpenAI disclosure, and OpenAI still hasn't stated a rationale itself. A daily cost set against lifetime revenue is also not a like-for-like comparison. But even read generously, the gap is stark. By these estimates, about two days of running cost would equal Sora's entire revenue. A standalone destination product has to earn its compute, and on these numbers Sora never came close.

Put together, the beat has moved. Last week, the story was what agent work costs. Now the constraint that matters is access. The open questions are which platforms will recognize an agent, on what terms, and who writes those terms. Two disclosures would settle the Amazon dispute. The first is whether Amazon offers any sanctioned path for an agent that identifies itself. The second is whether Meta answers the broader unauthorized-access charge, not just the credential claim. Until one of those arrives, assume the storefront, not the agent, decides who shops there.
