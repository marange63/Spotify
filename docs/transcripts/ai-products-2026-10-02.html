The last two days here covered dots, OpenAI's always-on agents, and the plugin extensions that came out of DevDay. Today's focus is the DevDay change that touches a developer's daily work: Codex, OpenAI's coding agent, moving fully into the cloud. One sourcing note up front. OpenAI's own DevDay pages still weren't reachable, so the Codex detail below comes from secondary reporting, mainly The Decoder and Simon Willison's live blog.

Here's the change. According to The Decoder, Codex tasks now keep running with your laptop closed, and you can start or check them from your phone. That sounds like a small convenience, but it resets the unit of coding work. Until now, a coding session was something you sat through. You opened the laptop, you watched the agent work, and you were the loop it ran inside. A delegated cloud task is different. You hand off a piece of work, close the laptop, and come back later to review what's done.

So the bottleneck moves. It's no longer your attention while the code gets written. It becomes your capacity to review what comes back. It also raises a governance question: who is accountable for code and credentials sitting inside OpenAI's cloud environment while nobody is watching. That's my analysis, not something OpenAI has said, but it follows from the design. And to be clear, cloud-run coding tasks aren't a new category. What changes is that the default now assumes the developer is absent.

OpenAI is at least addressing part of that governance question. A feature called Codex Security Cloud, which The Decoder describes as aimed at security teams, scans entire GitHub repositories on demand or on a schedule. Separately, it keeps checking new commits as they land. When it finds something, it investigates, filters out duplicates, and prepares a fix in the cloud, even when the laptop is closed. The reporting doesn't say whether a finding blocks a merge or is purely advisory. "Prepares fixes" suggests it proposes a remediation rather than gating anything, but that's an inference. The so-what is that OpenAI shipped an unattended security reviewer alongside the unattended coder, which reads as an acknowledgment that the review gap is real.

Two things remain unknown, and they're the ones that matter most for anyone budgeting around this. First, how cloud Codex tasks and their reusable environments are billed. Whether that draws down your plan allowance or gets metered separately by compute or task was not disclosed in any reporting checked for this briefing. Second, there's no usage or adoption figure anywhere. No count of tasks run, developers active, or pull requests merged. This is a day-one capability claim, not a track record.

One plan detail does help. Cloud Codex is available broadly, on Plus, Pro, Business, Enterprise, Edu, and Healthcare plans. It is not restricted to OpenAI's new five-hundred-dollar Pro tier.

That five-hundred-dollar tier matters for the other half of this story, which is Codex's second mode. Alongside unattended cloud tasks, OpenAI also shipped Ultrafast. The Decoder reports it generates up to 300 tokens per second in Codex, up to eight times faster than standard, and Pro 500 is the only Pro plan that gets it. So one product now sells a developer's time two different ways. Cloud tasks are for delegated, background work, where nobody's watching the clock. Ultrafast is for the opposite: interactive coding where a human is waiting on the output in real time. Same agent, two ways to buy it. For engineering leads, that means sorting their coding work into two buckets: the work worth paying to watch, and the work worth handing off.

Now, the model running underneath that agent is becoming a swappable, metered input, and the clearest proof is over at GitHub. On September 29th, the same day OpenAI unveiled its new mid-tier model, GPT-6.1 Sol, at DevDay, GitHub's changelog announced it generally available inside Copilot. It went to Copilot Pro+, Max, Business, and Enterprise users, across GitHub's IDE integrations, the Copilot CLI, and the coding agent. GitHub says that in early testing, the model "reliably completed tasks while using noticeably fewer tokens and steps" than earlier models in the GPT-6 and GPT-5.6 families. No figure is attached to that. And there's no independent comparison yet against the other models in Copilot's picker. Treat it as a vendor's early read, not a benchmark result.

Here's the part that matters commercially. GitHub says the new model "is billed at provider list pricing under usage-based billing." That's a shift worth naming out loud. On September 29th, this show's enterprise technology briefing noted GitHub cutting an Enterprise Copilot seat's included usage while holding the seat price. Now a brand-new model drops straight onto that same meter. GitHub keeps the developer relationship, the IDE, and the workflow. The model vendor becomes a priced line item inside it. One caution: GitHub describes the rollout as gradual, and Business and Enterprise admins control access through model policy. So "available everywhere on day one" overstates how many developers actually have Sol in hand today. My inference is that this augments the developer while commoditizing model choice inside the tool. GitHub owns the front door, and the labs compete for shelf space behind it.

Which brings us to the number that actually decides who wins. If you're billed by usage, the number that matters isn't the price per token. It's how many tokens a task takes. Two vendors are now explicitly selling on that number. GitHub, through its "fewer tokens and steps" claim about Sol. And Anthropic, with its new mid-tier model, Claude Sonnet 5.5. I should disclose that Anthropic makes the model behind this show.

Sonnet 5.5's unchanged list price and its speed and cost claims were covered here earlier this week. The relevant line is Anthropic's argument that the model needs far fewer tokens to do the same work, which it says makes a task roughly 30 percent cheaper. Two data points are new to this show.

The first is Terminal-Bench 4.0, an agentic coding-in-terminal evaluation. Anthropic reports Sonnet 5.5 scoring 70.6 percent, up from the prior model's 10.3 percent. That's Anthropic's own figure, relayed by SiliconANGLE, with no independent replication. A jump that large on one benchmark likely reflects a narrow slice of agentic tool-use behavior the old model handled poorly. Don't read it as a general coding capability claim.

The second is a customer result. Anthropic's materials quote Zendesk saying tickets were processed 20 percent faster after adopting the model. That's one customer's testimonial on one workload, not an audited case study. But it is a concrete, named workflow outcome rather than a demo claim.

So what's the pattern? GitHub on Sol, and Anthropic on Sonnet 5.5, are both pitching efficiency per completed task rather than a lower price per token. That's the price war, moved to a less visible number. And right now it's being fought entirely on vendor-reported figures, with no independent referee. Until someone runs the same real tasks through both models and publishes the token bill, buyers are pricing on faith.

Step back, and the arc of the week comes into focus. Coding agents are augmenting developers today, but they're quietly replacing the coding session as the basic unit of work. Once tasks run unattended and get billed by usage, spend scales with how much work you delegate, not how many seats you hold. That's my inference, and it's a real budgeting problem, because no vendor in this space has yet published a transparent per-task cost. Watch for three things from here.
